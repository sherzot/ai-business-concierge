# SPEC.md — AI Business Concierge

> Ежедневный AI-помощник по управлению бизнесом для узбекского предпринимателя
> Версия: 3.0 | Дата: 2026-05-06

---

## 1. О ПРОДУКТЕ

### 1.1 Одной строкой

AI Business Concierge — помощник для **ежедневного операционного управления** малым бизнесом, **уже работающим** в Узбекистане. В отличие от банковских инструментов, которые помогают открыть бизнес, мы рядом каждый день — налоги, кадры, договоры и продажи.

> **Ключевое отличие:** Банк AI → помогает НАЧАТЬ бизнес. Мы → помогаем его ВЕСТИ.

### 1.2 Проблема

В Узбекистане 403 800+ малых бизнесов. После открытия они сталкиваются с ежедневными операционными проблемами:
- **Налоги/бухгалтерия:** Не знают сроков сдачи отчётности → штрафы.
- **Договоры/документы:** 200-500K сумов за юриста → миллионы в месяц.
- **Продажи:** Вручную отвечают клиентам вечером/в выходные → теряют клиентов.
- **Кадры:** Не знают процедур найма/увольнения → нарушения трудового кодекса.

### 1.3 Решение

3 AI-модуля через Telegram-бот + Веб-дашборд — **каждый день, каждый час, на любой вопрос:**
1. **AI Советник** — налоги, бухгалтерия, кадры, бизнес-вопросы
2. **AI Документовед** — генерация договоров, заявлений, приказов (PDF/DOCX)
3. **AI Продавец** — создание и управление Telegram-ботом продаж

### 1.4 Аудитория

| Сегмент | Объём | Основная проблема | Польза от нас |
|---|---|---|---|
| ИП (индивидуальный предприниматель) | 200 000+ | Налоговая отчётность, договоры | Ежедневные AI-консультации, документы |
| Небольшой магазин/услуги | 150 000+ | Автоматизация продаж | Бот продаж, 24/7 ответы клиентам |
| Средний бизнес (10-50 сотрудников) | 50 000+ | Кадры, документы | HR-консультации, трудовые договоры |
| Бухгалтерские/юридические фирмы | 5 000+ | Документы для множества клиентов | Массовая генерация документов |

### 1.5 Конкурентный анализ

| Конкурент | Сильная сторона | Слабая сторона | Наше преимущество |
|---|---|---|---|
| **SQB "AI Советник"** | Госбанк, доверие | Только кредит/стартап | Ежедневные операции, Telegram |
| **My.soliq.uz** | Официальный, точный | Плохой UI, нет AI | AI + естественный язык + все модули |
| **ChatGPT** | Мощный AI | Не знает узбекских законов | База знаний по Узбекистану |
| **1C Бухгалтерия** | Полнофункциональный | Дорогой, сложный | Telegram, простота, AI-советы |

**Конкурентная стратегия:** Партнёрство с SQB — они дают кредит → клиент открывает бизнес → **приходит в наш бот** с ежедневными вопросами. Не конкурент, а воронка.

## 2. РОЛИ И РАЗРЕШЕНИЯ

### 2.1 Архитектура ролей

```
СИСТЕМНЫЙ УРОВЕНЬ
  super_admin  ≡  sub_admin  (одинаковые полные права)
      │
УРОВЕНЬ КОМПАНИИ
      └── company_admin
              ├── hr
              ├── accountant
              ├── manager
              └── employee
```

> **Важно:** `super_admin` и `sub_admin` имеют одинаковые права. Оба имеют полный доступ ко всем компаниям, системе, мониторингу и управлению.

## 11. ПРОЦЕСС РЕГИСТРАЦИИ КОМПАНИИ

### 11.1 Приём обращений

**Поля формы обращения:**
- ФИО / ответственное лицо
- Название компании
- ИНН (необязательно)
- Телефон *
- Email *
- Тип бизнеса (ИП / ООО / АО / Другое)
- Число сотрудников
- Основная проблема (необязательно)
- Откуда узнали

**Процесс:**
1. Форма отправлена → записывается в `contact_requests`
2. Email + уведомление super_admin/sub_admin
3. Admin просматривает → `contacted` → `invite_sent`
4. Система отправляет **одноразовый invite URL** на email компании (действует 48 часов)

### 11.2 Регистрация компании (Invite URL)

**Форма регистрации:**
- Компания: полное название, организационно-правовая форма, ИНН, адрес, банковские реквизиты
- Company Admin: имя, должность, телефон, email, пароль

**После регистрации:**
1. Аккаунт создаётся со `status: "pending_approval"`
2. Admin подтверждает → компания получает email «Аккаунт подтверждён!»
3. Если отказ → компания получает email + причину

### 11.3 Статусы аккаунта

```
contact_request → invite_sent → pending_approval → active → suspended / blocked
```

| Статус | Значение |
|---|---|
| `contact_request` | Форма отправлена |
| `invite_sent` | Invite URL отправлен |
| `pending_approval` | Зарегистрировался, ожидает подтверждения |
| `active` | Активен, полный доступ |
| `suspended` | Платёж не прошёл (3 дня grace) |
| `blocked` | Заблокирован администратором |

## 12. ПРОЦЕСС СОЗДАНИЯ АККАУНТА СОТРУДНИКА

### 12.1 Создание аккаунта HR-специалистом

**Форма нового сотрудника:**
- Личные данные: ФИО, дата рождения, пол, паспорт, ИНН, телефон, email, адрес
- Трудовые данные: должность, отдел, роль, дата приёма, зарплата, тип занятости
- Дополнительно: группа крови (необязательно), экстренный контакт

### 12.2 Автоматический процесс

```
1. HR отправляет форму
2. Система создаёт аккаунт (status: "password_pending")
3. На email сотрудника отправляется URL для установки пароля (24 часа)
4. Предупреждение HR: "Немедленно позвоните сотруднику"
5. Сотрудник устанавливает пароль
6. Предупреждение HR: "Ожидает вашего подтверждения"
7. HR подтверждает → сотрудник получает email «Аккаунт подтверждён!»
```

### 12.3 Статусы аккаунта сотрудника

```
password_pending → password_set → active → blocked
```

| Статус | Значение |
|---|---|
| `password_pending` | HR создал, сотрудник не установил пароль |
| `password_set` | Пароль установлен, ожидает подтверждения HR |
| `active` | HR подтвердил, полный доступ |
| `blocked` | Заблокирован HR или company_admin |
